# Contributing to Asperta
Thank you for your interest in contributing to Asperta! We strongly encourage community participation in this tool's development process. Please follow the guidelines below to ensure a smooth contribution experience.

Please contact the maintainers via Discord (@yupsie, @darcness) or GitHub issues if you have any questions or need assistance.

# Testing
Asperta does not currently have an automated test suite. If you would like to contribute tests, please reach out to the maintainers for guidance on how to get started. All changes should be tested with a local instance of the bot before submitting a pull request.

# Submitting Changes
Please send a pull request to [Europeia/recruitment-tool](https://github.com/Europeia/recruitment-tool) with a clear description of the changes you have made. If your changes are significant, please include a summary of the changes and any relevant context. 

Commits should be atomic (i.e., focused on a single change). Commit messages should follow the [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/#summary) specification. 

# Code Style
Asperta uses [Ruff](https://docs.astral.sh/ruff/) for linting and formatting. Please ensure that your code adheres to the style guidelines outlined in the [ruff.toml](https://github.com/Europeia/recruitment-tool/blob/main/ruff.toml) configuration file. You are encouraged to use [pre-commit](https://pre-commit.com/) or [prek](https://prek.j178.dev/) hooks to automatically format your code before committing, or you can manually run `ruff check` and `ruff format`. In future, we plan to enforce code style checks in our CI pipeline.

# AI Usage
We ask that any AI usage in contributed code be disclosed in the pull request description. This includes any code generated by AI tools or any AI-assisted development processes. Please provide details on how AI was used and any relevant context.

We will not accept contributions that are entirely generated by AI without human modification and review. All contributions will be reviewed and approved by a human maintainer before being merged into the main codebase.
